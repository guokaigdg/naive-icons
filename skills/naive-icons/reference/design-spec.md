# naive-icons 设计规范

本库的设计语言是**手绘 naive folk art（稚拙民间画）**：笨拙、温暖、有手作感，刻意保留不完美。
它不是「把线性图标加个圆角」——判断一张图是否属于本库，看的是气质，不是形状规整度。

本文档的每条规则都对照仓库内 163 枚现有图标核过。

---

## 1. 画布与根节点

所有图标共用同一根节点，163 枚**逐字节一致**：

```xml
<svg viewBox="0 0 48 48" xmlns="http://www.w3.org/2000/svg" fill="none"
     stroke="#2A2A2A" stroke-width="3.5"
     stroke-linecap="round" stroke-linejoin="round">
```

| 项 | 值 |
|---|---|
| viewBox | `0 0 48 48` |
| 默认描边 | `#2A2A2A`，宽 `3.5` |
| 线帽 / 线角 | `round` / `round` |
| 根 `fill` | `none` |

`3.5` 是相对 48 画布的。缩到 24px 视觉描边约 1.75px，缩到 16px 约 1.17px——这是本库在 16px
仍可辨的原因，**不要为了「看起来更细」而调小 stroke-width**。

## 2. 边距

主体（含描边外缘）距画布边缘 **≥ 3 单位**，即 48 宽画布里内容不超出 `3 ~ 45`。

> ⚠️ 按**描边外缘**算，不是按路径中心线。`stroke-width: 3.5` 会让描边向外扩 1.75，
> 中心线在 4.75 处就安全了，不是 3。忽略这点会做出贴边甚至出血的图标。

## 3. 调色板

10 色白名单：

| 名称 | 值 | 角色 |
|---|---|---|
| ink | `#2A2A2A` | 墨色，结构线与细节 |
| navy | `#264653` | 深蓝，冷色主体 |
| orange | `#E76F51` | 橙，强调与警示 |
| yellow | `#E9C46A` | 黄，暖色主体 |
| pink | `#F4A6A4` | 粉，柔和填充 |
| green | `#588157` | 绿，成功与自然 |
| teal | `#2A9D8F` | 青，主结构与循环 |
| brown | `#8B5E3C` | 棕，木质与土感 |
| cream | `#FAEDCD` | 奶油，深色底上的浅主体 |
| white | `#FFFFFF` | 白，仅用于在实色块上挖形（如勾、十字） |

**唯一例外**：`#4A8FD4` 品牌蓝，只出现在 `google-chrome`，因为它要还原 Chrome 标志的品牌识别。
新图标不要引入白名单外的颜色——确有必要时先想能不能用这 10 色凑出来。

## 4. 构图公式

163 枚里绝大多数遵循同一套三段式，这也是本库最容易被 AI 画错的地方：

```
主形体  = 一块大实心色（占视觉 60%+）
点缀    = 一处对比色小面积呼应
细节    = 墨色线条：表情、手部、轮廓转折
```

`check` 是范式：绿圆 `r=17` 实心 + 白勾 `4.5` 描边 + 墨色细节。
`users` 是范式：navy + orange + teal 三个实心块叠出两个人 + 墨色眼睛和微笑。

**不要**画成纯线条图标。163 枚里只有 **16 枚**没有实心填充，且都是「线条即语义」的类型——
方向与结构符号（`chevron-*`、`menu`、`link` / `unlink`、`paperclip`），
以及本来就是圈套符号的（`check-circle`、`x-circle`、`spinner`、`zoom-in` / `zoom-out`、`code`、
`check-square`、`external-link`）。

反直觉的一点：**`arrow-*` 四枚是有实心填充的**，因为箭头本质是「可被点击的色块」，
纯线条在 16px 下会太细。所以判断标准不是「方向符号就该线条化」，而是
**这个图形靠体积感还是靠走向被识别**。

## 5. 属性继承（最容易踩的坑）

根节点带 `stroke="#2A2A2A" stroke-width="3.5"`，所以**子元素不写 `stroke` 就会继承墨色描边**。
这通常是想要的（naive 味就来自这个描边），但有两个例外必须显式处理：

**① 不想有描边的填充形状 → 显式 `stroke="none"`**

```xml
<!-- ✗ 会继承 3.5 墨色描边，形状显得比预期大 -->
<path d="M… Z" fill="#E9C46A"/>

<!-- ✓ -->
<path d="M… Z" fill="#E9C46A" stroke="none"/>
```

**② 小面积彩色填充 → 显式收窄 `stroke-width`**

小三角会被继承的 3.5 描边整个包住，橙色几乎看不见：

```xml
<!-- ✓ 橙三角显式压到 3，图形才露得出来 -->
<path d="M40.7 23 L33 18.8 L41 14.2 Z" fill="#E76F51" stroke-width="3"/>
```

`refresh` 的两个箭头就是这么处理的。改动小图标时优先考虑放大图形，其次才是收窄描边。

## 6. 禁用项

163 枚全量扫描确认，以下一律不使用：

| 禁用 | 扫描结果 |
|---|---|
| 渐变 `linearGradient` / `radialGradient` | 0 枚 |
| 滤镜 `filter` | 0 枚 |
| 半透明 `opacity` | 0 枚 |
| 虚线 `stroke-dasharray` | 0 枚 |
| `mask` / `clipPath` / `pattern` | 0 枚 |
| 描边渐变叠加 | 0 枚 |

理由：naive 感来自**纯平涂色块 + 粗描边**。渐变和阴影会立刻把风格拉向现代扁平或拟物，两个方向都不对。

## 7. 允许 `transform`

10 枚在用：`bee`、`butterfly`、`cherry`、`donut`、`lemon`、`link`、`music`、`scooter`、
`snowflake`、`unlink`。

用途只有两种：**旋转/镜像复用已有图形**、**沿圆周排布重复元素**。

```xml
<!-- 镜像复用（link / unlink） -->
<g transform="translate(48,0) scale(-1,1)">

<!-- 沿圆周等分（snowflake） -->
<g transform="rotate(120 24 24)">
```

`scooter` 是**唯一**用了 `<g transform>` 的复合图形，库内其余图标的 body 全部顶格不缩进——
这是为了逐行比对 diff 方便，新图标请照此保持。

## 8. 尺寸可辨性

任何图标必须同时在 **16 / 24 / 48** 三档下成立：

- **16px** 是生死线。16px 下彩色点缀几乎看不见，靠**剪影**辨识。形体必须够简、够胖。
  `zoom-in` 最初做成实心镜片 + 小 `+`，在 16px 下 `+` 消失且和 `search` 撞脸，
  改成线框镜片 + 大符号才解决——**大符号 > 小符号**。
- **24px** 是默认尺寸，库里所有图标在这一档都是设计基准。
- **48px** 要能看到手作细节（眼睛、微笑、笔触），不糊成一坨。

同理：小尺寸下**不要**堆细节。`undo` / `redo` 的箭头必须够大，因为它们是主要识别特征。

## 9. 命名与组件名

- 图标 id：小写 + 连字符，`user-plus`、`volume-x`、`more-vertical`。
- 组件名：分段首字母大写 + `Icon`，`user-plus` → `UserPlusIcon`。由 id 机械推导，不要手写特例。
- 语义相近的成对图标要保持可预测的对称：`lock` / `lock-open`、`volume` / `volume-x`、
  `eye` / `eye-off`、`bell` / `bell-off`、`link` / `unlink`、`play` / `pause`。
  两枚应当**互为镜像或镜像对称**，这样用户在列表里能靠形状而非记忆区分。
